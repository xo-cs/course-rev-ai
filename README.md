# CourseRevAI

Course reviews for Woosong University students, plus **Broddy**, an AI course buddy that answers from the course catalog and student reviews. Built for the university AI competition festival.

- **Reviews**: search, filter and sort 207 courses (Spring 2025 timetable), read and write reviews (named or anonymous), AI review summaries, AI moderation, report button.
- **Broddy**: chat panel that knows the catalog, reviews, registration notes and your plan. Course mentions are verified against the catalog; it can add sections to My Courses and warns about timetable clashes.
- **My Courses / Calendar**: semester plan, credits counter, week calendar with clash display and preview blocks.
- **Admin dashboard** (`/admin`): charts, needs-attention list, professor table, AI insights, review moderation, CSV export.
- **Credits screenshot**: the "+" in Broddy reads a graduation-credits screenshot (Gemini image input), shows an editable table to confirm, then powers the Graduation progress card in My Courses and Broddy's advice.
- **/qr**: full-screen QR code of the site for the projector.

## Run locally

```bash
npm install
cp .env.example .env.local   # then fill in the values
npm run dev                  # http://localhost:3000
```

For a realistic speed check use `npm run build && npm start`.

### Environment variables

| Name | What it is |
| --- | --- |
| `GEMINI_API_KEY` | Google AI Studio key (server only) |
| `GEMINI_MODEL` | Main model, e.g. `gemini-3.5-flash-lite` |
| `GEMINI_FALLBACK_MODELS` | Comma-separated fallbacks, e.g. `gemini-3.8-flash` |
| `GROQ_API_KEY` | Optional last-resort fallback (OpenAI-compatible) |
| `GROQ_MODEL` | e.g. `openai/gpt-oss-120b` |
| `ADMIN_PASSCODE` | Passcode for `/admin` |

Keys are only read in server code (`lib/llm.ts`, route handlers). All LLM calls go through `lib/llm.ts`: main model, one retry on 503/429, fallback models, then Groq. It uses the Gemini **Interactions API** via `@google/genai`.

## Deploy (Vercel)

1. Import the GitHub repo in Vercel (framework: Next.js, default settings).
2. Add the environment variables above in **Settings → Environment Variables**.
3. Deploy. Every push to `main` redeploys. After changing env vars, redeploy.

## Admin dashboard: demo security only

`/admin` is protected by a single shared passcode (`ADMIN_PASSCODE`), checked on the server and remembered in an httpOnly cookie. **This is for the demo, not real security**: there are no user accounts, roles, rate limiting or audit log. Reviews written by users are stored per browser (localStorage) for this demo, so the dashboard shows the sample reviews plus reviews from the current browser, and Hide/Unhide applies to that browser.

## Project layout

```
app/(main)/        reviews list + course pages, My Courses, Calendar (three-column shell)
app/admin/         admin dashboard (passcode gate)
app/qr/            projector QR page
app/api/           chat (streaming), summarize, moderate, admin login/logout/insights
components/        shell, broddy, course, reviews, calendar, admin, ui
lib/               catalog, llm, broddyPrompt, schedule (clash logic), stores (localStorage)
data/              courses.json (generated by convert_courses.py), reviews.json (scripts/generate-reviews.mjs)
```

Regenerate sample reviews: `npm run gen:reviews`.
